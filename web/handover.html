One honest gap: Kharadi

Kharadi does not appear under 411014 — and cannot, from this data source.

The method derives place names from India Post's office directory, so it can only return places India Post has named an office after. Kharadi has no post office of its own. The only Kharadi B.O entries in the national directory are in Pali (Rajasthan) and West Nimar (Madhya Pradesh) — different places entirely.

The same applies to street-level names such as Waterfield Road or Pali Hill: real locations, but not postal offices, so no postal dataset contains them.

This is the boundary of the free authoritative data, and it affects a small number of informal urban colony names in metros. Two ways to close it:

OptionGets youCostCatch
LGD Villages
authoritative		 677,323 village → PIN rows. Strong rural and semi-urban coverage. Free. Needs the data.gov.in key. A village directory — still won't carry informal urban colony names.
OpenStreetMap
community		 Informal neighbourhood names like Kharadi, for chosen cities. Free. Hours of scraping per region. ODbL licence — share-alike on derived databases, unlike the GODL data used everywhere else. Needs a legal decision before it touches the master.

Recommendation: take LGD first — it is authoritative, free and carries no licensing question. Then measure what is genuinely still missing for the cities CK actually operates in before taking on ODbL obligations for a handful of names.

Deployed on the VPS: PostgreSQL 17 in Docker with a named volume, so the data survives every deploy. A browsable console and JSON API serve it live, with CSV downloads generated on request. A monthly refresh diffs each new government snapshot field by field and records every change, and it refuses any snapshot that would close more than 2% of offices — a truncated download is indistinguishable from a mass closure event. 22 regression tests and 10 integrity checks run on demand.

Before the onboarding form ships: 1,245 PIN codes span more than one district and 34 span more than one state. PIN 853204 alone covers five districts across 34 offices.

Never auto-fill district from PIN and treat it as verified. Show it as a default the candidate can override, and store what they confirmed. The API returns straddles_districts on every lookup for exactly this reason. This is the single most common cause of failed address matches in Indian applications.

Import

CREATE TABLE locality_lookup (
  pincode                 char(6) PRIMARY KEY,
  primary_district        text,
  primary_state           text,
  locality_names          text,
  total_localities_count  int,
  status                  text
);

\copy locality_lookup FROM 'pincode_localities.csv' CSV HEADER;
CREATE INDEX ON locality_lookup (primary_district);

Rebuild it after each monthly refresh — the file regenerates automatically as part of the export step, so it will not drift from the master.

Source: Department of Posts, Government of India, via data.gov.in. Government Open Data Licence – India (GODL): free commercial use, attribution required. Boundary polygons are a community compilation — verify before regulatory use.
